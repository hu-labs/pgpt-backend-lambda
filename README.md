# PromptGPT Backend (AWS Lambda)

The backend for PromptGPT.

A serverless REST API running on AWS Lambda, providing LLM response from OpenAI API.

Designed to serve the frontend in the pgpt-frontend repository.

## Stack

- **AWS Lambda** for serverless compute
- **API Gateway** for the REST API interface
- **AWS Secrets Manager** for secret management
- **AWS Cognito** for authentication
- **DynamoDB** for conversation and preset storage
- **AI SDK** for LLM integration
- **Node.js 24** runtime

## Testing

A complete pre-deployment check can be run manually with:

```bash
npm run check
```

This verifies formatting, lint rules, and unit tests. GitHub Actions runs the same check before deployment and follows deployment with a smoke test.

For local authenticated tests against deployed stacks, see [the smoke-test instructions](scripts/lib/README.md).

## Conversation and preset API

All endpoints require an API Gateway verified Cognito ID token and an API key.
The caller identity comes exclusively from the authorizer claims. Paths below are
relative to `/api/v1` through CloudFront, or `/test` on the preview API Gateway.

| Method | Path                                       | Body / response                                                             |
| ------ | ------------------------------------------ | --------------------------------------------------------------------------- |
| GET    | `/threads`                                 | `{threads}` sorted by most recently updated                                 |
| POST   | `/threads`                                 | Optional `{title}`; send `{}` for the default title; returns a thread (201) |
| GET    | `/threads/{threadId}`                      | Returns thread metadata                                                     |
| PATCH  | `/threads/{threadId}`                      | `{title}`; returns updated metadata                                         |
| DELETE | `/threads/{threadId}`                      | Deletes messages then metadata (204)                                        |
| GET    | `/threads/{threadId}/messages`             | `{messages,nextCursor}`; pass `?cursor=...` for the next page               |
| POST   | `/threads/{threadId}/messages`             | `{content}`; creates a user message (201)                                   |
| PATCH  | `/threads/{threadId}/messages/{messageId}` | `{content}`; edits only the selected message                                |
| DELETE | `/threads/{threadId}/messages/{messageId}` | Deletes the selected message (204)                                          |
| GET    | `/presets`                                 | `{presets}` sorted by most recently updated                                 |
| POST   | `/presets`                                 | `{title,text}`; creates and returns a prompt preset (201)                   |
| PATCH  | `/presets/{presetId}`                      | `{title}`, `{text}`, or both; returns the updated preset                    |
| DELETE | `/presets/{presetId}`                      | Deletes the selected preset (204)                                           |
| POST   | `/chat`                                    | `{threadId,content}`; streams `delta`, then `done` or `error`               |

Titles are trimmed and limited to 1–100 characters. User content is trimmed and
limited to 1–5000 characters. IDs are generated by the backend. Unknown body
fields are rejected. Missing caller-owned resources return 404. Invalid inputs
return 400, unsupported methods 405, and unexpected failures 500.

Preset titles use the same 1–100 character limit. Preset text is trimmed and
limited to 1–5000 characters. Threads, messages, and presets share the same
DynamoDB table and are partitioned by the verified Cognito `sub`, so list and
mutation operations expose only the caller's records.

`/chat` loads the latest 30 stored messages and uses server-side model
`gpt-4o-mini` at temperature `0.7`. It saves the new user message before generation,
then saves the complete assistant response before sending
`done` with `{userMessageId,assistantMessageId}`. Generation failure keeps the user
message and emits `error` without storing a partial assistant response.

Lambda requires `DYNAMODB_TABLE_NAME` and `OPENAI_SECRET_ID`. AWS credentials and
region come from the Lambda runtime. `OPENAI_API_KEY` remains a local debugging
override. API Gateway must supply the `allowedOrigin` stage variable.
